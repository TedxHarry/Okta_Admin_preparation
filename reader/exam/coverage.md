## Part I · Active Directory Integration (47%)

| Objective | Course coverage and practice |
| --- | --- |
| Delegated authentication with AD and LDAP | **Planned · Active Directory and LDAP.** Configure each integration and test delegated sign-in. Compare AD Just-in-Time (JIT) creation on first sign-in with onboarding through import. Inspect the user link, selected OUs, and sign-in evidence. |
| AD and LDAP agent architecture and practices | **Published · [Connect Active Directory to Okta](../week-04-ad-and-ldap/lessons/01-connect-active-directory.md).** Install and verify one AD agent and identify network and runtime dependencies. **Planned · Active Directory and LDAP.** Verify LDAP agent setup and AD failover on separate Windows agent hosts. |
| Service accounts and password-reset permissions | **Planned · Active Directory and LDAP.** Distinguish the installer, Okta registration account, and runtime service identity. Compare the directory permissions for reads, password reset, and provisioning writes. Test a reset with scoped permissions. |
| Okta and AD password policies | **Planned · Active Directory and LDAP.** Follow authentication and password changes to the system that enforces the policy. Compare the result for an Okta-managed user and a delegated AD user. |
| AD-sourced user activation | **Planned · Active Directory and LDAP.** Choose import scope, match a new and an existing user, and compare confirmation, activation, and email settings. Run manual imports and compare full, incremental, and scheduled behavior. Inspect import safeguards and use a fresh account to test JIT eligibility. |
| AD groups and Okta groups | **Published foundation · [Group sources and ownership](../modules/manage-groups/01-identify-the-group-and-its-owner.md) and [Groups and membership rules](../week-01-foundations/lessons/03-groups-and-membership-rules.md). Published lab · [Import groups and trace source ownership](../modules/manage-groups/07-import-groups-and-trace-source-ownership.md).** Import a disposable AD group, trace a source-side change, and optionally verify the app assignment. A simulated exercise is available without AD. |

For the real AD lab, use a test domain, a Windows agent host, and an Okta org that supports the integration. The AD failover lab adds a second host. The LDAP lab needs a reachable test LDAP server. A course org by itself lets you study the configuration and investigate the evidence described in the lessons. [Okta's AD learning path](https://learning.okta.com/path/integrate-with-active-directory) · [AD integration prerequisites](https://help.okta.com/oie/en-us/Content/Topics/Directory/ad-agent-prerequisites.htm)
