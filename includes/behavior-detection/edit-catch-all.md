## Lab 3 · Modify the Catch-All Rule { #lab-3 }

Complete Lab 2. The practice requirement is password plus an additional factor for a group member whose browser is new, and password for requests that reach the fallback. Make the password-only change in the isolated lab policy only. When a practice or exam prompt names settings, follow those settings.

1. Open **Security → Authentication Policies → App sign-in** and select the policy you configured in Lab 2. Check **Applications** for the expected app. On **Rules**, record the current Catch-All action, factor requirement, and reauthentication setting. Also record the behavior rule and its priority.
2. Select the **Catch-All Rule** edit control in the Rules tab. Keep its general matching scope. Set **Access is** to **Allowed after successful authentication** and select **Password** under **User must authenticate with**. Save. The labels may group Password under one factor type. Keep the existing reauthentication setting unless the practice requirement specifies a change, and record what the editor saves.
3. Reopen both rules. Verify the behavior rule still requires **Password + Another factor** and is above the Catch-All Rule. Verify the fallback now requires **Password**. The member with an unfamiliar browser can match the first rule. A request outside the group or with a false expression can reach the fallback.
4. Inspect the **Global Session Policy** that applies to the lab users. If its matching session rule already requires MFA, the fallback sign-in may still show another prompt. Record that separate requirement. For a clean prompt comparison in a disposable org, you can use a test-only global session policy assigned to `BD Lab Learners` with a password session and MFA **Not required**. Place it ahead of the broader matching policy, keep administrators outside that test group, and restore the lab changes at the end. You can also leave session requirements in place and compare which app rule the System Log records.
5. Keep the new fallback through Lab 4 and the guided retest. For cleanup, restore the captured settings exactly if you edited an existing policy, or reattach the app to its original policy before removing your dedicated lab policy.

**Evidence to save for practice:** the original and changed fallback settings, policy-to-app association, both rules in priority order, and the relevant global session MFA setting.
