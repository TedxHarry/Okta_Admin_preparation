# Course screenshot guidance

Use wide or full screenshots in lessons and labs so readers can see where each control lives. Keep the page heading, relevant sidebar or breadcrumb, and target control in the same view whenever the layout permits. Show the navigation path nearby when it helps readers identify the page.

Before saving or publishing, remove or permanently redact names, emails, org URLs and identifiers, dates and timestamps (including Created and Last modified), credentials, and any other private details. Review the actual image pixels before adding the asset to the repository. Keep enough of the interface visible to orient the reader and provide useful alt text.

## Course lab coverage

Map every objective and configuration task in the Okta Administrator Performance Exam guide to its theory and practice. Explain what each concept does, why it matters, and how to verify it. Give learners a hands-on exercise for each configuration and a practical observation or investigation for each concept. Call out the required org features, test data, and permissions when they affect the exercise. If a task needs a different environment, document that dependency and keep the task in the coverage plan.

Keep all configuration, testing, and troubleshooting steps when a lab grows. Keep a short lab on one page when the learner benefits from seeing it all at once. Use a few numbered task tabs when they make distinct stages easier to find or keep a screenshot beside the relevant steps. When a lab has many tasks, group related tasks into named sublabs under Hands-on Lab. Aim for approximately four to five tasks per sublab and adjust the grouping when a workflow is easier to follow together. Keep the original task order and show any prerequisites or dependencies between sublabs. Place screenshots beside the steps they illustrate.

## Lesson writing and production

Use GPT-6.2 Sol at medium reasoning for writing lessons, verifying Okta behavior and exam coverage, and designing hands-on labs when that model configuration is available. Use a lower-cost model for routine screenshot capture, redaction, image placement, publishing, and rendering checks when delegation is available.

Give the production pass a short brief with the lesson and repository paths, exact screens and controls to capture, redaction requirements, and what to verify after publication. Keep the final technical and privacy review with the writing pass.
